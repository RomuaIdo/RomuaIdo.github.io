## Context and problem

The goal was to build a complete processor at the RTL level, with no off-the-shelf IP: from the ALU to the control unit, each block with its own testbench, simulated in GHDL and inspected as waveforms in GTKWave. The acceptance test was running a non-trivial program written in the processor's own ISA.

## Architecture and technical decisions

```ascii title="Simplified datapath"
            +-------+    17 bits    +------+
   PC ----->|  ROM  |-------------->|  IR  |----> control unit
   ^        | 128x17|               +------+        (4 states)
   |        +-------+                  |
   |                         Rx (4 bits) | constant 8/12 bits
   |                                     v
   |                        +----------------------+
   |                        | R1..R15 file (R0=0)  |
   |                        +----------+-----------+
   |                                   |
   |        +-----+      +-----+       v
   +--------| ACC |<-----| ALU |<---- Rx / constant
 (branches) +-----+      +-----+
               |            |
               v            v  C Z N OV
        +-------------+  +----------+
        | RAM 256x16  |  |  status  |
        | [Rx + cst]  |  +----------+
        +-------------+
```

**Accumulator machine.** Every arithmetic operation has the accumulator as source and destination (`ADD A,Rx`, `SUB A,Rx`). This reduces the instruction to a single register field and simplifies the datapath, at the cost of more moves (`MOV A,Rx` / `MOV Rx,A`) in the assembly.

**17-bit instruction.** A 5-bit opcode and four formats: register (`ooooo rrrr xxxxxxxx`), immediate to register with an 8-bit constant, immediate to the ALU with a 12-bit constant, and branch with a 7-bit address or offset. With one bit beyond the 16 of data, 12-bit constants fit in the instruction itself, fetched in a single ROM access.

**R0 fixed at zero.** The file has 15 physical registers; address `0000` always reads zero. `MOV A, R0` clears the accumulator without a dedicated instruction.

**Multicycle with four states.** Fetch, decode, execute (ALU and register writes), and a fourth state for memory access and branches. The program counter is written at fetch and, if the branch is taken, in the fourth state.

**Signed and unsigned flags and branches.** Subtraction is done as `a + not(b) + 1` in 17 bits, so the carry is the inverse of the borrow (*not-borrow*): `C = 1` means there was no borrow. Unsigned branches use this directly (`BLS`: `C = 0` or `Z = 1`; `BCC`: `C = 0`). Signed ones combine `N` and `OV` (`BGT`: `N = OV` and `Z = 0`). The zero flag is computed only over the 16 bits of the result, ignoring the carry bit.

## Implementation

### ALU

The ALU produces a single 17-bit signal from which the result and flags are derived. The `CTZ` operation (count trailing zeros) is a priority chain over the operand bits:

```vhdl
aluout_result <= ('0' & a) + ('0' & b)                    when op = "00" else
                 ('0' & a) + ('0' & not(b)) + 1           when op = "01" else  -- carry = not-borrow
                 shift_left('0' & a, to_integer(b))       when op = "10" else  -- SLL
                 to_unsigned(0, 17) when op = "11" and b(0) = '1' else         -- CTZ
                 to_unsigned(1, 17) when op = "11" and b(1) = '1' else
                 -- ...
                 to_unsigned(16, 17) when op = "11" else                       -- operand = 0
                 (others => '0');

z  <= '1' when aluout_result(15 downto 0) = 0 else '0';
ov <= '1' when (op = "00" and a(15) = b(15) and aluout_result(15) /= a(15)) or
               (op = "01" and a(15) /= b(15) and aluout_result(15) /= a(15)) else '0';
```

### Sieve of Eratosthenes

The program fills `RAM[i] = i` and then clears the multiples of each prime. Two custom instructions shorten the loops:

- `SLL A, R9` with `R9 = 9` shifts the index nine bits to the left; the carry goes to 1 when the index reaches 128, and `BCC` ends the fill without a comparison.
- `CTZ A, R1` is 7 exactly when `R1 = 128`, the stop criterion of the prime search.

```asm
popula:              ; RAM[i] = i, i = 0..127
  MOV A, R1
  STA [R1 + 0]
  ADDI 1
  MOV R1, A
  SLL A, R9          ; carry out when i reaches 128
  BCC popula

sieve:               ; clear multiples of the current prime
  ADD R1
  CMPI 128
  BGT is_prime
  MOV R3, A
  MOV A, R0          ; R0 is always zero
  STA [R3 + 0]
  MOV A, R3
  JMP sieve
```

At the end, the nonzero RAM positions between 2 and 127 are the primes.

### Verification

Each block has its own testbench in `tb/` (ALU, registers, file, PC, ROM, datapath, control unit, and top level). The `Makefile` analyzes, elaborates, and runs any top level in GHDL with `--std=08` and writes the `.ghw` waveform for GTKWave.

## Results and next steps

- Complete processor simulated, running the sieve over the numbers up to 127 in a 256-word RAM.
- 23 instructions, including memory with `[Rx + constant]` addressing and signed and unsigned relative branches.

Next steps:

- Expose the primes found on an output bus for debugging, instead of inspecting them in the RAM through the waveform.
- Extend the sieve to use all the available RAM.
- Generate the register file with `for ... generate` in place of the 15 hand-written instances.
- A dedicated assembler for the `.asg` files.
