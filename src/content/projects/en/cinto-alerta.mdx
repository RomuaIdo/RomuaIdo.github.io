## Context and problem

The severity of a fall in elderly people depends less on the impact and more on the **time until help arrives**. Someone who falls alone at home and cannot get up may spend hours on the floor. Calling for help by phone fails precisely in the worst cases: loss of consciousness, a broken hip, or the phone in another room.

Cinto Alerta is an academic prototype with two nodes:

- **Belt** (ESP32-S3 SuperMini, battery powered): reads an IMU, classifies the motion on the device itself and, on a fall, vibrates and lights an LED for a few seconds before sending the alert.
- **Base** (ESP32-S3-DevKitC-1 N16R8, plugged into the wall): receives the alert over ESP-NOW and notifies caregivers through Telegram.

It is not a medical device: there is no clinical validation, and the training data comes from falls simulated by young adults.

## Architecture and technical decisions

```ascii title="System overview"
+--------------------+   ESP-NOW (direct radio)  +----------------------+
|        BELT        | ------------------------> |         BASE         |
| ESP32-S3 SuperMini |   Alert / AlertAck        | ESP32-S3 N16R8       |
| BMI270 (SPI, FIFO) |                           | AP+STA, web portal   |
| 1D CNN (TinyML)    |                           | queue in LittleFS    |
+--------------------+                           +----------+-----------+
                                                            | HTTPS
                                                            v
                                                  +-------------------+
                                                  |   Telegram Bot    | --> caregiver
                                                  +-------------------+
```

**Waist, not wrist.** The initial idea was a watch. The wrist moves independently of the body: slapping a table, clapping, or taking the watch off produce signatures similar to a fall. The waist follows the center of mass and only really moves when the whole body moves.

**Cancellation window.** Telling "fell" apart from "sat down quickly on the couch" is still an unsolved problem. The window turns a critical false alarm into a button press, and each cancellation is a real "not a fall" example for improving the model.

**ESP-NOW instead of the home Wi-Fi.** The belt talks directly to the base. Since only the base knows the router's channel, pairing starts at the belt, which scans channels 1 to 13 with a broadcast `PairRequest` and locks onto the channel where it heard the base. The base only stores the belt after a `PairConfirm`.

**IMU over SPI with FIFO.** The IMU in use is the Bosch **BMI270**, read over `SPI` with a FIFO interrupt: the sensor accumulates samples and the ESP32-S3 reads them in bursts, instead of waking up for every sample. The integration is in development branches and has not reached the main branch yet, which keeps the previous driver, an MPU-6050 over `I2C`.

**Always-available base.** The base runs in AP+STA mode: it keeps its own network (`CintoAlerta-Master`) for configuration from a phone and, at the same time, connects to the router to reach Telegram.

## Implementation

My part is the base firmware, a PlatformIO project (Arduino framework) organized by responsibility:

| Layer | Responsibility |
|---|---|
| `App/AppController` | Coordinates Wi-Fi, NTP, the alert queue, Telegram delivery, and the portal |
| `Web/WebPortal` | HTTP server and API for the configuration page, served from LittleFS |
| `Network/EspNowTransceiver`, `PairingService` | ESP-NOW reception and the pairing state machine |
| `Messaging/TelegramTask` | Asynchronous delivery in FreeRTOS tasks (up to 2 concurrent) |
| `Storage/CallQueueStorage`, `ConfigStorage` | Resend queue and `config.json` persisted in LittleFS |

### Protocol

Every frame starts with a packed 7-byte header, shared between belt and base:

```cpp
#pragma pack(push, 1)
struct Header {
    uint32_t magic;     // 0x42454C54, "BELT"
    MessageType type;   // PairRequest, PairWait, PairAccept, PairConfirm, Alert, AlertAck
    uint16_t seq;       // replies echo the seq they answer
};
#pragma pack(pop)
```

Frames with an unexpected `magic`, type, or size are discarded. The belt resends an `Alert` with the same `seq` until it receives the matching `AlertAck`.

### Resend queue

Each alert becomes a file in `/queue` on LittleFS before any delivery attempt, so a power loss does not lose the event. At startup, corrupted or already delivered files are removed. Network failures and HTTP 5xx or 429 responses are retried with exponential backoff:

$$
d_0 = 5\,\text{s}, \qquad d_{n+1} = \min(2\,d_n,\; 300\,\text{s})
$$

400 or 403 responses discard only the affected chat, without blocking the other recipients.

### Tests

Domain, storage, network, and messaging have Unity suites that run on the board (`pio test`), including persistence tests that write to flash and reboot tests. The web interface can be opened without hardware with `?mock`, which simulates the firmware API.

Next steps:

- Bring the BMI270 integration (SPI + FIFO) and the model to the main branch.
- Validate on the belt the 1D CNN trained on the SisFall dataset, which is currently in development branches.
- Implement the heartbeat: a belt with a dead battery, frozen, or out of range is indistinguishable from an elderly person who is fine. The base should warn the caregiver when the signals stop, with a message distinct from a fall.
- Pairing through the belt button; today registration is manual, by MAC address in the portal.
